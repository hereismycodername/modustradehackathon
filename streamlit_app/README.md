# Демо на Streamlit Community Cloud

Эта папка запускает весь Django-сайт без изменений внутри приложения Streamlit.
Страница Streamlit показывает сайт во фрейме, а сам сайт работает по адресу
`django/` того же приложения. Функции, дизайн, роли и демо-данные те же, что
при обычном запуске. Остальной код проекта эта папка не меняет.

## Как задеплоить

1. На [share.streamlit.io](https://share.streamlit.io) нажмите **Create app** и выберите развёртывание из GitHub.
2. Заполните форму:
   - **Repository:** `hereismycodername/modustradehackathon`
   - **Branch:** `main`
   - **Main file path:** `streamlit_app/streamlit_app.py`
3. В **Advanced settings** выберите **Python 3.13**, как в проекте.
4. Нажмите **Deploy**. Первая сборка занимает несколько минут.

## Вход

Логины указаны на странице входа: `hack_author`, `hack_processor`,
`hack_coordinator` для сценария защиты, а также `author`, `processor`,
`coordinator`, `manager`, `admin`. Пароль для всех — `ModusDemo2026!`. Он же
показан в верхней полосе страницы.

## Секреты (необязательно)

В настройках приложения: **Settings → Secrets**, формат TOML.

```toml
DEMO_PASSWORD = "свой-пароль-не-короче-12-символов"
DJANGO_SECRET_KEY = "длинная-случайная-строка"   # иначе ключ создаётся заново при каждом запуске

# Уведомления: те же переменные, что в ../.env.example.
# EMAIL_HOST, EMAIL_HOST_USER, EMAIL_HOST_PASSWORD, DEFAULT_FROM_EMAIL,
# TELEGRAM_BOT_TOKEN, TELEGRAM_BOT_USERNAME, BITRIX24_WEBHOOK_URL.
# SITE_URL — адрес сайта из строки браузера после «Открыть на весь экран»,
# без завершающей косой черты; он нужен для ссылок в письмах и сообщениях.
```

Без секретов всё работает: письма пишутся в журнал приложения, Telegram и
Битрикс24 не используются.

## Ограничения

- База — SQLite во временной папке. Когда Streamlit перезапускает приложение
  или будит его после периода без посетителей, введённые данные пропадают, а
  демо-данные загружаются заново. Перед защитой откройте ссылку заранее.
- Обработчик уведомлений работает в том же процессе, отдельный worker не нужен.
- Внутри фрейма браузер не ставит курсор в поле входа сам: щёлкните по полю.
- Если браузер со строгими настройками cookies не даёт войти во фрейме,
  нажмите «Открыть на весь экран».
- Это демонстрационный стенд, а не пилот. Для реальных данных нужен запуск из
  основного README: PostgreSQL, Docker, отдельный worker.

Если после деплоя ссылки внутри сайта ведут не туда, добавьте в секреты
`STREAMLIT_PATH_PREFIX` — часть адреса перед `/django/`, которую видно в
строке браузера после «Открыть на весь экран» (например, `"/~/+"`).

## Локальный запуск

```bash
python3 -m venv .venv-streamlit
.venv-streamlit/bin/pip install -r streamlit_app/requirements.txt
.venv-streamlit/bin/streamlit run streamlit_app/streamlit_app.py
```

Откройте http://localhost:8501.

## Как устроено

| Файл | Назначение |
| --- | --- |
| `streamlit_app.py` | `st.App`: при старте применяет миграции и загружает демо-данные, запускает обработчик уведомлений и подключает Django по адресу `/django/` |
| `page.py` | Страница Streamlit: полоса с паролем и фрейм с сайтом |
| `demo_settings.py` | Надстройка над `config/settings.py`: DEBUG выключен, адреса с префиксом, разрешение показывать сайт во фрейме Streamlit |
| `static_storage.py` | Адреса CSS и JS строятся от префикса текущего запроса |
| `requirements.txt` | Зависимости для Streamlit Cloud: Streamlit и те же версии, что в `../requirements.txt` |

Streamlit Cloud открывает приложение под дополнительной частью адреса (например,
`/~/+/`) и убирает её до того, как запрос дойдёт до приложения. Django узнаёт
эту часть из адреса страницы, открывшей сайт, и запоминает её в cookie, поэтому
все ссылки, формы и файлы ведут туда, куда нужно.
